GitNym

Names that are searchable — and actually available on npm, PyPI and domains.

Honest limits, read this first: GitHub repo names are unique per owner only, so this tool never claims a GitHub repo name is globally unique. Scores below are transparent heuristics, not proof and not measured user data. Availability badges are per-source results, or “unchecked” when a check fails.

Press Enter in the description box to generate. No key needed. Scoring works offline; live badges degrade to “unchecked” offline or on rate limits.

How scores are calculated (published weights)

Length 25% · Pronounceability 25% · Typo-resistance 20% · Searchability 15% · Memorability 15% (SUBJECTIVE — a heuristic, not measured recall). Click a name's breakdown to see each part. Searchability only warns about similarity to a small popular-names list — it never marks a GitHub repo name “Taken”.

      What this does NOT claim

      • It does not claim a GitHub repo name is globally unique — it cannot be, per owner.
      • It does not claim scores predict success, memorability in real users, or virality.
      • Domain results, when shown, are “hint only — resolves does not mean available”. A resolving domain can still be owned, parked, or unavailable.
      • Domain check is attempted via DNS-over-HTTPS only; if that request fails in your browser, the domain badge becomes “unchecked” and the check is cut for that session, not guessed.
      • GitHub badge checks whether a GitHub account (user/org) with that exact name exists. That is not a repo-uniqueness check.
      • No BYOK / AI mode in v1. Generation is deterministic: the same inputs give the same top 10 in the same order.
